# Заявки автосервиса из Telegram

Telegram-бот принимает заявки клиентов, пока мастер занят машиной, а владелец разбирает их в веб-кабинете (CRM).

Клиент пишет боту своими словами. LLM один раз определяет услугу и достаёт из сообщения то, что клиент уже сказал.
Дальше бот без LLM задаёт только недостающие вопросы формы услуги, спрашивает телефон, показывает заявку и отправляет
её в CRM после подтверждения клиента.

## Как это выглядит для владельца

1. Регистрируется: название автосервиса, имя, email, пароль.
2. Вставляет токен бота из [@BotFather](https://t.me/BotFather).
3. Бот запускается сам. Типовые услуги с вопросами уже добавлены, их можно менять в разделе «Услуги».

По желанию мастер открывает одноразовую ссылку из кабинета, и бот присылает ему каждую новую заявку в Telegram.

## Запуск

```sh
cp .env.example .env
# впишите JWT_SECRET, а для распознавания свободного текста — LLM_API_KEY и LLM_MODEL
docker compose up --build
```

Кабинет откроется на http://localhost:3000. Публичный адрес и вебхуки не нужны: бот получает сообщения через long polling.

### Настройки

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | PostgreSQL |
| `JWT_SECRET`, `JWT_TTL` | сессии сотрудников; секрет не короче 32 символов, срок сессии по умолчанию `720h` (30 дней) |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | любой OpenAI-совместимый API (`/chat/completions`): OpenAI, OpenRouter, локальный сервер. Пустой `LLM_MODEL` отключает LLM — клиент выбирает услугу кнопкой |
| `LLM_TIMEOUT` | таймаут запроса к LLM, по умолчанию `20s` |
| `APP_URL` | публичный https-адрес кабинета; добавляет в уведомление мастеру кнопку «Открыть в CRM» |
| `BOT_RUNNER` | `false` отключает раннер ботов внутри `serve` (тогда его запускают отдельно командой `bot`) |
| `BOT_API_KEY` | необязательно: включает internal API `/internal/v1` для внешних интеграций |
| `TELEGRAM_API_URL` | адрес Bot API, по умолчанию `https://api.telegram.org` |

Ключ LLM один на всю установку, владельцам автосервисов он не нужен.

Забытый пароль сотрудника сбрасывает администратор сервера: команда печатает новый пароль и завершает все сессии
этого аккаунта.

```sh
docker compose exec api ./app reset-password owner@example.com
```

## Как устроен бот

```
/start            → «Здравствуйте! Чем могу помочь?»
свободный текст   → LLM: услуга + уже названные поля формы (+ телефон, если он в сообщении)
                    не поняла или недоступна → кнопки со списком услуг
недостающие поля  → по одному вопросу; выбор — кнопками, необязательные можно пропустить
телефон           → кнопка «Отправить мой номер» или текстом
подтверждение     → «Отправить» / «Изменить» / «Отменить»
заявка            → CRM + сообщение подписанным мастерам
```

- LLM вызывается только пока услуга не определена. Её ответ считается недоверенным: значения проверяются по типам
  полей, лишнее отбрасывается, а итог клиент всё равно подтверждает сам.
- Состояние диалога хранится в PostgreSQL, перезапуск ничего не теряет.
- Раннер каждые несколько секунд сверяет запущенные боты с таблицей `bots`: новый токен подхватывается без рестарта,
  заменённый или отключённый — останавливается. Что видит раннер (работает, токен отозван, конфликт), показано в кабинете.
- При нескольких репликах бэкенда Telegram опрашивает одна: лидер держит advisory-лок PostgreSQL, остальные ждут.
- Команды клиента: `/my` — свои заявки и отмена ещё не взятых в работу, `/cancel` — прервать заполнение.

## Показатели

Бэкенд отдаёт метрики Prometheus на `/metrics`: воронку онбординга, конверсию диалогов бота, долю сообщений,
распознанных LLM, и её стоимость в токенах, скорость реакции мастера, зависшие заявки, состояние ботов.
Что означает каждая метрика и когда беспокоиться — в [docs/DESIGN.md](docs/DESIGN.md), раздел 10.

## Структура

```
backend/   Go: HTTP API (chi), PostgreSQL (pgx), бот
  cmd/                       serve | bot | migrate | probe | reset-password
  internal/domain            сущности и правила: услуги, формы, заявки, статусы
  internal/usecases          сценарии кабинета и операции бота
  internal/bot               диалог (engine.go) и раннер long polling (runner.go)
  internal/gateway/postgres  репозитории и миграции
  internal/gateway/telegram  клиент Bot API
  internal/gateway/llm       клиент OpenAI-совместимого API и промпт
  internal/testkit           фейковые Telegram и LLM для тестов
frontend/  Next.js: кабинет (заявки, клиенты, услуги, автосервис и бот)
deploy/    манифесты Kubernetes
```

## Тесты

```sh
cd backend
go test ./...                                    # без базы: домен, диалог бота, клиент LLM
TEST_DATABASE_URL=postgres://... go test ./...   # плюс сквозные; схема public в этой базе будет пересоздана
```

Сквозные тесты поднимают настоящий раннер против фейкового Telegram: онбординг, диалог клиента, заявка в CRM,
уведомление мастеру, перезапуск раннера посреди диалога, замена и отзыв токена.

```sh
cd frontend && npm ci && npm run lint && npm run build
```
